## ROOT CAUSE (measured, not inferred)

Our Q8_0 GEMV is **memory-LATENCY-bound**, not bandwidth-, occupancy-, alignment-, or
launch-count-bound. At 71.9% occupancy the warps do not have enough *independent* memory
loads in flight to hide the load→unpack→`__dp4a` dependency chain (long-scoreboard 54.4).
The 16× sector over-fetch from the 34-byte-misaligned blocks is real but **L1 absorbs
96.7% of it**, which is exactly why the three prior structural fixes were flat:
- Brick 4 (aligned repack) — fixed alignment, not the latency chain → flat.
- Brick 11 (sub-warp occupancy) — split lanes, REDUCING ILP if anything → flat.
- Brick 12 (launch consolidation) — the graph already amortized launches → flat.

## THE ONE UNTRIED, MEASUREMENT-POINTED LEVER

**Latency-hiding via ILP: multiple output-rows per thread** — each thread computes N
output rows, issuing N *independent* weight-load streams so the compute of row i hides
the load latency of row i+1. This raises in-flight memory parallelism (lowers
long-scoreboard) WITHOUT changing occupancy/alignment/launch-count. This is the axis
none of Bricks 4/11/12 touched. ds4's 90% (existence proof, same bytes) is consistent
with ds4 running more independent loads per thread.
