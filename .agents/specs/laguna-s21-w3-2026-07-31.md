## Risks/decisions

1. **Dual-RoPE numerics** — the YaRN inv_freq is REUSED (gated upstream); the
   laguna-NEW compose (partial rotary_dim + explicit mscale + layout) is bit-
   matched vs a hand reference here, but W4 must still bit-match the cos/sin cache
   vs the llama.cpp fork on the REAL config rows (the numerics-delicate flag).
2. **Variable Q-head** — the host reference exercises 2-vs-4 heads; the DEVICE
   runner still needs the per-layer Q-head-COUNT + GQA-group extension (Gemma-4
   G1b did per-layer KV head_dim, not Q-count) — a W4 device-path residual.
3. **Router tie-break** — the razor is unit-pinned (lower index), but a real greedy
   gate can still diverge on a near-tie the way Qwen3-dense did; W4 verifies vs the
   oracle's actual selection.
4. **Reference vs production numerics** — the W3 forward is f32 whole-sequence; the
   production path is bf16 paged. Token-exactness across that boundary is a W4
   concern, not claimed here.
