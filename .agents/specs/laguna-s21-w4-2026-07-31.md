### 3. Three CPU-verified fidelity corrections (grounded in the real GGUF + llama.cpp)
Each was WRONG in the W1-W3 scaffold and is now fixed + unit-gated
(`test_laguna_scaffold`), each a genuine residual the scope flagged or missed:

- **(a) Per-head QK-RMSNorm** — the GGUF ships `attn_q_norm`/`attn_k_norm`
  F32[head_dim]. Laguna RMS-norms each head's q and k vector BEFORE RoPE (the
  Qwen3/OLMo-2 pattern). `config.json` has no `qk_layernorm` flag, so the W0-W3
  scope MISSED it entirely; it surfaces only in the tensor map. Added
  `has_qk_norm` + `q_norm`/`k_norm` weights + `RmsNormHeads` in the forward.
- **(b) Dual-RoPE mscale = llama.cpp formula** — `mscale = yarn_attn_factor *
  (1 + 0.1*ln(factor))` (`LagunaYarnMscale`), computed off the GGUF-authoritative
  `factor=32` / `yarn_attn_factor=1.0` → **1.34657**, NOT the HF-precomputed
  `attention_factor=1.4852` (which is the 1M-ctx, factor-128 value). The formula
  reproduces BOTH (HF's 1.4852 == `1+0.1*ln(128)`), so the safetensors path stays
  correct while the same-quant GGUF path matches llama.cpp. Resolves the flagged
  "dual-RoPE must bit-match llama.cpp" numerics residual for the mscale term.
- **(c) Separate expert gate/up** — the GGUF has separate `ffn_gate_exps` +
  `ffn_up_exps` (not a merged `gate_up`); dense L0 likewise `ffn_gate`+`ffn_up`;
  shared likewise. Forward + weight structs corrected.
