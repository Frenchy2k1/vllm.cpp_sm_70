## Risks/decisions

1. **Per-layer VARIABLE Q-head count (48 global / 72 sliding)** — the runner does
   per-layer KV head_dim (Gemma-4 G1b) but not per-layer Q-head COUNT + variable
   GQA group (6 vs 9). Medium risk, mechanical (attn metadata + per-layer q_proj
   shape). W3.
2. **Dual RoPE × partial-rotary(0.5) × YaRN mscale(1.4852) on ONLY the full-attn
   64 dims** — three reused pieces that must COMPOSE; numerics-delicate. Gate the
   cos/sin cache bit-for-bit vs the llama.cpp fork. W3. Medium risk.
3. **Ungrouped sigmoid-noaux router tie-break** — ds2/glm4 are GROUPED; peel to the
   ungrouped path (drop the group step) + apply routed_scaling to OUTPUT + renorm;
   gate the top-10 selection + tie-break razor (Qwen3-dense precedent). Low-medium.
4. **Per-head softplus attention output gate** — the one genuinely-new op; must
   match `softplus(g_proj(x).float()).type_as` fp32 + per-head broadcast exactly.
   Low risk (`Softplusf` exists). W3.
5. **ORACLE-BLOCKED fallback** — if the pin cannot construct `LagunaConfig` without
   remote code and it is disallowed, the vLLM NVFP4 golden is blocked ⇒ llama.cpp
   -only same-quant gating (still valid, ds4 precedent). De-risked by the W1
   config-constructs check before any GPU time.
6. **Memory** — UD-Q4_K_XL ~73.4 GiB fits GB10's 119 GiB unified pool; keep
   `gpu_memory_utilization` low (unified-pool OOM-reboot hazard); never co-run a
   big vLLM NVFP4 oracle beside our engine.
